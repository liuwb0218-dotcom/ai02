# AI 智能问答平台 — 需求说明

> 版本：v0.1（Day19-21 本期交付）
> 对齐文档：《ai问答平台v1.docx》第一、二、三、五、八节

## 一、项目目标与本期范围

用户可以选择不同模型、输入问题、获取 AI 回答，并能查看和软删除自己的历史会话记录。
本期按"先跑通最小闭环，再逐步扩展"推进，只交付 P0 内容：

- 5 个核心接口：`/health`、`/api/models`、`/api/chat`、`/api/history/{user_id}`、`DELETE /api/history/{session_id}`
- 4 个模型配置接口（本次新增）：`POST /api/models`、`PATCH/DELETE /api/models/{id}`、`POST /api/models/{id}/test`
- 4 张核心表：`users`、`chat_sessions`、`api_call_logs`、`model_configs`
- 6 个核心模块 + 统一异常处理
- 两份交付文档：本文件与《接口测试记录.md》

本期模型能力（本次增强）：

- 内置模型：`mock`、`deepseek-chat`（走 `.env` 配置）、`local`（本地 Ollama 等 OpenAI 兼容服务）
- 用户可在运行时自由切换以上模型
- 用户可自建模型配置（新增 / 修改 / 停用 / 删除 / 连通性测试），仅本人可见可用
- 自建配置的 `api_key` 以 AES-256-GCM 加密入库，任何响应都不返回 Key

不在本期范围（P1/P2）：注册登录/JWT、RAG 知识库、管理员后台、多模态图片、反馈闭环、会话导出、定时清理、完整 12 表方案。

## 二、核心功能

| 编号 | 功能 | 本期实现 |
|------|------|----------|
| 3 | AI 对话核心 | 基础问答 + session_id；SSE 与延伸问题为 P1 |
| 4 | 用户可切换模型 | 内置 `mock` / `deepseek-chat` / `local` 三选一，`model_name` 指定；用户自建模型与内置模型可混用 |
| 6 | 会话管理 | 每次问答即建 `chat_sessions` 记录；历史倒序查询；软删除 |
| 11 | 安全防护（基础） | 参数校验、空问题拦截、未知模型拦截、不允许越权查询 |
| 13 | 可观测性 | 每次模型调用写 `api_call_logs`（模型、耗时、状态、错误信息） |

## 三、六个核心模块

| 序号 | 模块 | 实现文件 | 职责 |
|------|------|----------|------|
| 1 | 用户管理 | `app/services/user_service.py` | 识别 user_id、校验会话归属，保证用户 A 不能查 B 的历史 |
| 2 | 模型配置 | `app/core/config.py`、`app/services/model_config_service.py`、`app/services/llm_client.py` | 内置模型与用户自建模型统一存储、加密 Key、解析调用目标、连通性测试 |
| 3 | 模型会话 | `app/schemas/chat.py`、`app/services/chat_service.py` | 参数校验、调用模型、落库并返回回答 |
| 4 | 历史记录 | `app/services/history_service.py` | 按用户查询、时间倒序、软删除与归属校验 |
| 5 | 日志记录 | `app/services/chat_service.py` | 每次调用写 `api_call_logs`，成功失败都写 |
| 6 | 异常处理 | `app/core/exceptions.py`、`app/main.py` | 统一异常类型、错误码、HTTP 状态码、错误响应格式 |

## 四、接口清单

| 编号 | 接口 | 方法 | 请求 | 成功响应 |
|------|------|------|------|----------|
| 1 | `/health` | GET | 无 | `{"status":"ok","message":"AI QA Platform is running"}` |
| 2 | `/api/models` | GET | 可选 `user_id` | `{"models":[{"id":1,"model_name":"mock","display_name":"Mock 模型（本地联调）","provider":"mock","base_url":null,"upstream_model":null,"has_api_key":false,"is_builtin":true,"is_enabled":true}, ...]}` |
| 3 | `/api/chat` | POST | `{"user_id":1,"question":"你好","model_name":"mock"}` | `{"session_id":1,"answer":"...","model_name":"mock","latency_ms":58,"status":"success"}` |
| 4 | `/api/history/{user_id}` | GET | 路径 `user_id`；可选 `limit`(默认20)、`offset`(默认0) | `{"user_id":1,"total":2,"items":[...]}` |
| 5 | `/api/history/{session_id}` | DELETE | 路径 `session_id` | `{"deleted":true,"session_id":1}`，重复删除返回同样结果 |
| 6 | `/api/models` | POST | `{"user_id":1,"name":"my-model","display_name":"我的模型","provider":"local","base_url":"http://127.0.0.1:11434/v1","upstream_model":"qwen2.5:7b","api_key":""}` | 返回配置详情（含 `id`、`has_api_key`） |
| 7 | `/api/models/{config_id}` | PATCH | 任意可改字段：`display_name`/`base_url`/`upstream_model`/`api_key`/`is_enabled` | 返回更新后的配置详情 |
| 8 | `/api/models/{config_id}` | DELETE | 路径 `config_id` | `{"deleted":true,"id":4}`，仅可删本人自建配置 |
| 9 | `/api/models/{config_id}/test` | POST | 路径 `config_id` | `{"success":true,"latency_ms":873,"answer_preview":"..."}`，失败返回 502 |

模型配置规则：

- `provider` 取值：`mock`（系统内置）、`deepseek`、`local`、`custom`
- `name` 只允许字母数字与 `._-`，长度 2~40，同用户下唯一；重名返回 409
- 内置模型（`owner_user_id` 为空）不可修改、不可删除；用户自建模型仅本人可见可用
- `base_url` 只允许 http/https，禁止内嵌账号密码，禁止指向云主机元数据地址
- `api_key` 可留空（本地模型常见），落库前 AES-256-GCM 加密，响应只回 `has_api_key`

约定：

- 统一 UTF-8 JSON，请求头 `Content-Type: application/json`
- 本期用 `user_id` 区分用户；请求头 `X-User-Id` 模拟当前登录用户，接入 JWT 后改为从 Token subject 取
- `question` 长度 1-2000；`model_name` 必须在 `/api/models` 列表中
- 删除为软删除：`is_deleted=1`、`deleted_at=当前时间`

## 五、四张核心表

### users（用户表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 用户主键 |
| username | TEXT | UNIQUE NOT NULL | 登录名/显示名 |
| created_at | TEXT | NOT NULL DEFAULT (datetime('now','localtime')) | 创建时间 |

### chat_sessions（会话历史表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 会话/问答记录主键 |
| user_id | INTEGER | NOT NULL; FK users.id | 会话所属用户 |
| model_name | TEXT | NOT NULL | 本次问答使用的模型名 |
| question | TEXT | NOT NULL | 用户问题 |
| answer | TEXT | NOT NULL | AI 回答 |
| created_at | TEXT | NOT NULL DEFAULT (datetime('now','localtime')) | 历史列表按此倒序 |
| is_deleted | INTEGER | NOT NULL DEFAULT 0 | 软删除标记 |
| deleted_at | TEXT | NULLABLE | 软删除时间 |

索引：`idx_session_user(user_id)`、`idx_session_user_created(user_id, created_at)`

### api_call_logs（模型调用日志表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 日志主键 |
| user_id | INTEGER | NOT NULL | 调用用户 |
| session_id | INTEGER | NULLABLE | 关联 chat_sessions.id；失败时为空 |
| model_name | TEXT | NOT NULL | 实际调用的模型名 |
| status | TEXT | NOT NULL CHECK(status IN ('success','error')) | 调用状态 |
| latency_ms | INTEGER | NOT NULL DEFAULT 0 | 调用耗时（毫秒） |
| error_message | TEXT | NULLABLE | 失败原因 |
| created_at | TEXT | NOT NULL DEFAULT (datetime('now','localtime')) | 调用时间 |

索引：`idx_log_user_created(user_id, created_at)`

### model_configs（模型配置表，本次新增）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT | 配置主键 |
| owner_user_id | INTEGER | NULLABLE; FK users.id | 空=系统内置模型，非空=用户自建 |
| name | TEXT | NOT NULL | 模型标识，`/api/chat` 的 `model_name` 取值 |
| display_name | TEXT | NOT NULL | 前端展示名称 |
| provider | TEXT | NOT NULL CHECK IN ('mock','deepseek','local','custom') | 调用协议 |
| base_url | TEXT | NULLABLE | OpenAI 兼容地址；mock 为空 |
| upstream_model | TEXT | NULLABLE | 上游真实模型名，如 `deepseek-chat`、`qwen2.5:7b` |
| api_key_encrypted | TEXT | NOT NULL DEFAULT '' | AES-256-GCM 密文；空表示免鉴权 |
| is_enabled | INTEGER | NOT NULL DEFAULT 1 | 停用后不出现在列表、不可被选择 |
| created_at | TEXT | NOT NULL DEFAULT (datetime('now','localtime')) | 创建时间 |
| updated_at | TEXT | NOT NULL DEFAULT (datetime('now','localtime')) | 更新时间 |

索引：`uidx_model_owner_name(owner_user_id, name)` 唯一

> 12 表完整方案的映射见需求文档 5.1：`users`→`user`、`chat_sessions`→`chat_session`+`message`、`api_call_logs`→`chat_log`、`model_configs`→`llm_model`。

## 六、异常处理

所有业务异常继承 `AppException`（`message` / `code` / `status_code`），由 `app/main.py` 注册的全局处理器统一转换，错误响应带 `request_id`。

| 异常类 | 错误码 | HTTP | 触发场景 |
|--------|--------|------|----------|
| ValidationException | VALIDATION_ERROR | 422 | 参数缺失、question 为空、长度超限 |
| PermissionDeniedException | FORBIDDEN | 403 | 访问他人会话 |
| NotFoundException | NOT_FOUND | 404 | 用户、会话或模型配置 ID 不存在 |
| ModelNotFoundException | MODEL_NOT_FOUND | 404 | model_name 不在可选列表或配置已停用 |
| ConflictException | CONFLICT | 409 | 用户自建模型标识重名 |
| ModelCallException | MODEL_CALL_FAILED | 502 | 模型超时、5xx、网络失败、未配置 Key |
| DatabaseException | DB_ERROR | 500 | 建表、写入、查询或事务失败 |
| AppException | APP_ERROR | 500 | 未知业务错误兜底 |

统一错误响应：

```json
{
  "success": false,
  "code": "MODEL_NOT_FOUND",
  "message": "模型 'xxx' 不存在",
  "detail": {"available_models": ["mock", "deepseek-chat"]},
  "request_id": "req_5c519197b60f"
}
```

## 七、调用链路

```
POST /api/chat
  → app/api/routes.py           接收请求
  → app/schemas/chat.py         参数校验
  → app/services/chat_service.py 业务编排
      → app/services/user_service.py          校验用户
      → app/services/model_config_service.py  解析 model_name（本人自建优先 → 内置）
      → app/services/llm_client.py            调用模型（mock / OpenAI 兼容）
  → 写 chat_sessions + api_call_logs
  → 返回 ChatResponse
```

模型解析细节：

```
model_config_service.resolve(user_id, name)
  → 查 owner_user_id = 本人 且 is_enabled=1 的记录
  → 未命中则查 owner_user_id 为空的内置记录
  → 仍未命中：404 MODEL_NOT_FOUND，detail 带回可选模型
  → 命中：AES-256-GCM 解密 api_key（仅内存），本地模型超时 60s、远程 10s
```

任何一层抛出异常 → `app/core/exceptions.py` 定义的类型 → `main.py` 全局处理器 → 统一错误 JSON（保留服务端日志与 request_id）。
