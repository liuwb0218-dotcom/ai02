# AI 智能问答平台 — 需求说明

> 版本：v1.0（Day19-21 交付 + 认证 / 公告 / 日志迭代）
> 对齐文档：《ai问答平台v1.docx》第一、二、三、五、八节；《培训文档_Day19-21》验收标准

## 一、项目目标与本期范围

用户注册登录后选择不同模型提问、查看与软删除自己的历史会话；管理员审核用户、发布公告、查看全员调用日志；普通用户在「我的数据」查看账号信息与用量统计。

已交付能力：

- 问答主链路：`/health`、`/api/models`、`/api/chat`、`/api/history/{user_id}`、`DELETE /api/history/{session_id}`
- 模型配置：`POST /api/models`、`PATCH/DELETE /api/models/{id}`、`POST /api/models/{id}/test`
- 认证：注册 / 登录 / 刷新 / 登出 / 修改密码 / 当前用户，JWT 双 Token
- 公告：用户端待读列表与已读上报；管理端列表 / 新建 / 编辑 / 撤回
- 日志：用户端汇总与列表、管理端全员日志、技术日志文件、每日清理
- 管理：用户列表、单人审核、批量审核、审计留痕
- 8 张表：`users`、`user_tokens`、`audit_log`、`chat_sessions`、`api_call_logs`、`model_configs`、`announcements`、`announcement_reads`
- 11 个模块 + 统一异常处理
- 4 个前端页面：登录页、问答页、管理后台、我的数据
- 两份交付文档：本文件与《接口测试记录.md》

模型能力：

- 内置模型：`mock`、`deepseek-chat`（走 `.env` 配置）、`local`（本地 Ollama 等 OpenAI 兼容服务）
- 用户可在运行时自由切换以上模型
- 用户可自建模型配置（新增 / 修改 / 停用 / 删除 / 连通性测试），仅本人可见可用
- 自建配置的 `api_key` 以 AES-256-GCM 加密入库，任何响应都不返回 Key

不在本期范围（后续迭代）：RAG 知识库、多模态图片、文件上传、问题推荐、多轮上下文、SSE 流式输出、会话导出、反馈闭环、限流与配额（异常类型已预留）。

## 四、接口清单

### 4.1 问答与模型

| 编号 | 接口 | 方法 | 请求 | 成功响应 |
|------|------|------|------|----------|
| 1 | `/health` | GET | 无 | `{"status":"ok","message":"AI QA Platform is running"}` |
| 2 | `/api/models` | GET | 无（身份取自 Token） | `{"models":[{"model_name":"mock","display_name":"Mock 模型（本地联调）","provider":"mock","base_url":null,"upstream_model":null,"has_api_key":false,"is_builtin":true,"is_enabled":true}, ...]}` |
| 3 | `/api/chat` | POST | `{"question":"你好","model_name":"mock"}` | `{"session_id":1,"answer":"...","model_name":"mock","latency_ms":58,"prompt_tokens":4,"completion_tokens":27,"total_tokens":31,"status":"success"}` |
| 4 | `/api/history/{user_id}` | GET | 路径 `user_id`（仅本人）；可选 `limit`(默认20)、`offset`(默认0) | `{"user_id":1,"total":2,"items":[...]}` |
| 5 | `/api/history/{session_id}` | DELETE | 路径 `session_id` | `{"deleted":true,"session_id":1}`，重复删除返回同样结果 |
| 6 | `/api/models` | POST | `{"name":"my-model","display_name":"我的模型","provider":"local","base_url":"http://127.0.0.1:11434/v1","upstream_model":"qwen2.5:3b","api_key":""}` | 返回配置详情（含 `id`、`has_api_key`） |
| 7 | `/api/models/{config_id}` | PATCH | 任意可改字段：`display_name`/`base_url`/`upstream_model`/`api_key`/`is_enabled` | 返回更新后的配置详情 |
| 8 | `/api/models/{config_id}` | DELETE | 路径 `config_id` | `{"deleted":true,"id":4}`，仅可删本人自建配置 |
| 9 | `/api/models/{config_id}/test` | POST | 路径 `config_id` | `{"success":true,"latency_ms":873,"answer_preview":"..."}`，失败返回 502 |

模型配置规则：

- `provider` 取值：`mock`（系统内置）、`deepseek`、`local`、`custom`
- `name` 只允许字母数字与 `._-`，长度 2~40，同用户下唯一；重名返回 409
- 内置模型（`owner_user_id` 为空）不可修改、不可删除；用户自建模型仅本人可见可用
- `base_url` 只允许 http/https，禁止内嵌账号密码，禁止指向云主机元数据地址
- `api_key` 可留空（本地模型常见），落库前 AES-256-GCM 加密，响应只回 `has_api_key`

约定：

- 统一 UTF-8 JSON，请求头 `Content-Type: application/json`
- 除 `/health`、`/api/auth/*`、`/login` 外，业务接口一律要求 `Authorization: Bearer <access_token>`，用户身份取自 Token，不再接受客户端传 `user_id`
- access token 30 分钟、refresh token 7 天；刷新时轮换 refresh，旧记录置 `revoked_at`
- `question` 长度 1-2000；`model_name` 必须在 `/api/models` 列表中
- 删除为软删除：`is_deleted=1`、`deleted_at=当前时间`

### 4.3 页面路由

| 路径 | 说明 |
|------|------|
| `/login` | 登录 / 注册页 |
| `/` | 问答页（侧栏「使用统计」「我的数据」或「管理后台」） |
| `/admin` | 管理后台（用户审核 / 公告管理 / 调用日志；超管另有「分组」标签），非管理员显示无权限页 |
| `/me` | 我的数据（账号信息、近 30 天统计、最近调用与问答） |

### 4.4 分组规则

- 归属字段为 `users.managed_by`，只有普通用户参与分组；管理员与超管始终为 `NULL`
- 分配时机：注册时即按「活跃管理员（`role=admin` 且 `status=active`，按 ID 升序）」轮询写 `managed_by`，第 1 个用户给第 1 个管理员，第 2 个给第 2 个，依次循环；没有管理员时保持未分配
- 权限范围：普通管理员的用户列表、计数、审核/禁用、批量审核、调用日志一律强制 `managed_by = 自己`；跨组操作返回 403「只能管理本组用户」
- 管理员变更：超管撤销或禁用某管理员时，组内用户转给当前人数最少的管理员（并列取 ID 小者）；若已无其他管理员则置为未分配。存量用户不做重排，新注册用户按轮询补位
- 超管视图：`GET /api/admin/groups` 汇总每个管理员的待审核/已审核/已禁用/合计，以及未分配总数与其中待审核数；「未分配」只统计普通用户
- 手动调整：超管可用 `PATCH /api/admin/users/{id}/manager` 把某个普通用户改到另一位活跃管理员，或置空移回未分配；用户表「归属」列即为该操作的下拉入口，每次调整写 `audit_log`（`reassign_user`）

## 五、数据表（8 张）

| 字段 | 类型 | 约束 | 说明 |

| disabled_until | TEXT | NULLABLE | 临时禁用到期时间；空表示永久 |

| last_login_at | TEXT | NULLABLE | 最近登录时间 |
| token_version | INTEGER | NOT NULL DEFAULT 0 | 登出/改密/禁用时 +1，旧 Token 立即失效 |

## 六、异常处理

所有业务异常继承 `AppException`（`message` / `code` / `status_code`），由 `app/main.py` 注册的全局处理器统一转换，错误响应带 `request_id`。

| 异常类 | 错误码 | HTTP | 触发场景 |
|--------|--------|------|----------|
| ValidationException | VALIDATION_ERROR | 422 | 参数缺失、question 为空、长度超限 |
| AuthenticationException | UNAUTHORIZED | 401 | 未登录、Token 缺失/无效/过期 |
| AccountDisabledException | ACCOUNT_DISABLED | 403 | 账号被禁用（detail 带原因与到期时间） |
| TrialExpiredException | TRIAL_EXPIRED | 403 | 试用到期且未审核，禁止问答 |
| PermissionDeniedException | FORBIDDEN | 403 | 访问他人会话、非管理员访问管理接口 |
| NotFoundException | NOT_FOUND | 404 | 用户、会话或模型配置 ID 不存在 |
| ModelNotFoundException | MODEL_NOT_FOUND | 404 | model_name 不在可选列表或配置已停用 |
| ConflictException | CONFLICT | 409 | 用户自建模型标识重名 |
| ModelCallException | MODEL_CALL_FAILED | 502 | 模型超时、5xx、网络失败、未配置 Key |
| DatabaseException | DB_ERROR | 500 | 建表、写入、查询或事务失败 |
| AppException | APP_ERROR | 500 | 未知业务错误兜底 |

统一错误响应：

```json
{
  "success": false,
  "code": "MODEL_NOT_FOUND",
  "message": "模型 'xxx' 不存在",
  "detail": {"available_models": ["mock", "deepseek-chat"]},
  "request_id": "req_5c519197b60f"
}
```

## 七、调用链路

```
POST /api/chat（Authorization: Bearer <access_token>）
  → app/api/deps.py               get_current_user：验签、token_version、禁用/试用期拦截
  → app/api/routes.py             接收请求
  → app/schemas/chat.py           参数校验
  → app/services/chat_service.py  业务编排
      → app/services/model_config_service.py  解析 model_name（本人自建优先 → 内置）
      → app/services/llm_client.py            调用模型（mock / OpenAI 兼容）
                                              返回 answer + latency + prompt/completion tokens
  → 写 chat_sessions + api_call_logs（成功、失败都写）
  → 返回 ChatResponse（含 token 三字段）
```

模型解析细节：

```
model_config_service.resolve(user_id, name)
  → 查 owner_user_id = 本人 且 is_enabled=1 的记录
  → 未命中则查 owner_user_id 为空的内置记录
  → 仍未命中：404 MODEL_NOT_FOUND，detail 带回可选模型
  → 命中：AES-256-GCM 解密 api_key（仅内存），本地模型超时 60s、远程 10s
```

任何一层抛出异常 → `app/core/exceptions.py` 定义的类型 → `main.py` 全局处理器 → 统一错误 JSON（保留服务端日志与 request_id）。

## 八、日志与可观测性

### 8.1 调用日志

| 场景 | 写入内容 |
|------|----------|
| 调用成功 | `status=success`、`session_id`、`latency_ms`、三个 token 字段、`error_message` 为空 |
| 调用失败 | `status=error`、`session_id` 为空、`latency_ms=0`、token 全 0、`error_message` 记异常原因 |
| 模型不存在 | 在解析阶段被拦截，返回 404，不构成一次模型调用，不写日志 |

Token 计算口径：

1. 真实模型优先取上游响应 `usage.prompt_tokens / completion_tokens / total_tokens`
2. 上游未返回 `usage` 时，按 `ceil(字符数 / 1.5)` 估算，输入与输出分别计算
3. mock 模型无上游，直接对问题与回答套估算公式
4. 失败调用记 0

查询与保留：

- 用户端：`GET /api/logs/summary?days=30`（本人汇总）、`GET /api/logs`（本人明细），强制 `user_id=当前登录用户`
- 管理端：`GET /api/admin/logs`，可按 `user_id` / `status` / `model_name` / `days` 筛选；超管看全员，普通管理员只看本组用户
- `api_call_logs` 仅保留 `LOG_RETENTION_DAYS`（默认 30）天，每天 03:00 由 APScheduler 调 `log_service.purge_old_logs` 清理
- `audit_log` 为管理员操作留痕，永久保留，不参与清理

### 8.2 技术日志

- `app/core/logging.py` 的 `setup_logging()` 在导入 `main` 时初始化：控制台 + 文件双输出
- 文件路径 `LOG_DIR/app.log`（默认 `./logs/app.log`），级别 `LOG_LEVEL`（默认 INFO）
- `TimedRotatingFileHandler`：每天零点轮转，历史文件后缀 `%Y-%m-%d`，`backupCount=LOG_RETENTION_DAYS`，最多保留 30 份
- 日志只记录请求方法、路径、状态码、耗时、错误码、request_id，不写问题与回答正文
- `logs/` 已加入 `.gitignore`，不入库

## 十、本地模型与超时（实测记录）

本机为纯 CPU 推理（Ollama `/api/ps` 显示 `size_vram=0`），没有 GPU 加速：

| 模型 | 冷启动（含加载） | 常驻后 | 备注 |
|------|------------------|--------|------|
| qwen2.5:7b (Q4_K_M) | 56.9s | 7~13s | 冷启动已逼近 60s 读超时边界 |
| qwen2.5:3b | 9.5s | 约 4s | 当前内置 `local` 默认模型 |

结论与配置：

- `LOCAL_MODEL_NAME=qwen2.5:3b`，`LOCAL_MODEL_TIMEOUT_SECONDS=60`；3B 下超时余量充足
- Ollama 默认闲置 5 分钟卸载模型；若切回 7B，需设 `OLLAMA_KEEP_ALIVE=-1` 常驻，或把本地超时提到 180s
- 本地 `prompt_tokens` 会包含对话模板开销（如 13 字问题报 35 token），属于上游 `usage` 的真实口径
- 调用 Ollama 时若本机开启系统代理，需保证 `127.0.0.1` 在 `NO_PROXY` 中，否则会被代理拦截导致超时
