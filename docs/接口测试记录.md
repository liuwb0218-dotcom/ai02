## 二、用例明细

### 1. 健康检查

```
GET /health
```

响应 200：

```json
{"status": "ok", "message": "AI QA Platform is running"}
```

### 2. 模型列表

```
GET /api/models
```

响应 200：

```json
{"models": [{"model_name": "mock", "display_name": "Mock 模型"}, {"model_name": "deepseek-chat", "display_name": "deepseek-chat"}]}
```

### 3. mock 问答

```
POST /api/chat
{"user_id": 1, "question": "你好", "model_name": "mock"}
```

响应 200：

```json
{"session_id": 1, "answer": "这是 mock 模型的回答：你好（当前为本地联调模式，未调用真实大模型）", "model_name": "mock", "latency_ms": 58, "status": "success"}
```

### 4. 真实模型问答（2026-10-28 复测通过）

```
POST /api/chat
{"user_id": 1, "question": "用一句话介绍你自己", "model_name": "deepseek-chat"}
```

响应 200（耗时 0.9s）：

```json
{"session_id": 8, "answer": "我是DeepSeek，由深度求索公司创造的AI助手，致力于用热情细腻的方式帮助你探索信息、解决问题。", "model_name": "deepseek-chat", "latency_ms": 873, "status": "success"}
```

说明：早期 `.env` 未配 Key 时该用例返回 502；现 Key 已配置，真实模型链路完整跑通，
`api_call_logs` 同步写入一条 `status='success'`、`latency_ms=873` 的记录。

### 5. 本地模型问答（Ollama 未启动，预期 502）

```
POST /api/chat
{"user_id": 1, "question": "hi", "model_name": "local"}
```

响应 502（约 5s 返回，connect 超时与推理超时分开设置）：

```json
{"success": false, "code": "MODEL_CALL_FAILED", "message": "模型 local 连接超时（5s），请确认 http://127.0.0.1:11434/v1 可访问", "detail": null, "request_id": "req_..."}
```

启动 Ollama 并 `ollama pull qwen2.5:7b` 后重测即可得到 200。

### 6. 历史查询

```
GET /api/history/1?limit=20&offset=0
```

响应 200（两条记录，session_id=2 在前）：

```json
{"user_id": 1, "total": 2, "items": [
  {"session_id": 2, "question": "再问一次", "answer": "这是 mock 模型的回答：再问一次（...）", "model_name": "mock", "created_at": "2026-10-27 16:34:01"},
  {"session_id": 1, "question": "你好", "answer": "这是 mock 模型的回答：你好（...）", "model_name": "mock", "created_at": "2026-10-27 16:34:01"}
]}
```

### 7. 越权查询

```
GET /api/history/2
X-User-Id: 1
```

响应 403：

```json
{"success": false, "code": "FORBIDDEN", "message": "无权访问其他用户的数据", "detail": null, "request_id": "req_7f24780b7750"}
```

### 8. 软删除与幂等

```
DELETE /api/history/1
```

第一次 200：`{"deleted": true, "session_id": 1}`
第二次 200：`{"deleted": true, "session_id": 1}`

### 9. 空问题

```
POST /api/chat
{"user_id": 1, "question": "", "model_name": "mock"}
```

响应 422：

```json
{"success": false, "code": "VALIDATION_ERROR", "message": "请求参数校验失败",
 "detail": [{"type": "string_too_short", "loc": ["body", "question"], "msg": "String should have at least 1 character"}],
 "request_id": "req_8c858099e8e6"}
```

### 10. 非法模型

```
POST /api/chat
{"user_id": 1, "question": "hi", "model_name": "nope"}
```

响应 404：

```json
{"success": false, "code": "MODEL_NOT_FOUND", "message": "模型 nope 不存在或已停用",
 "detail": {"available_models": ["mock", "deepseek-chat", "local", "my-ollama"]}, "request_id": "req_b9109ddc5008"}
```

### 11. 模型配置：新增 / 重名 / 越权 / 隔离

新增（200）：

```
POST /api/models
{"user_id":1,"name":"my-ollama","display_name":"我的本地 Ollama","provider":"local",
 "base_url":"http://127.0.0.1:11434/v1","upstream_model":"qwen2.5:7b","api_key":""}
```

```json
{"id":4,"model_name":"my-ollama","display_name":"我的本地 Ollama","provider":"local",
 "base_url":"http://127.0.0.1:11434/v1","upstream_model":"qwen2.5:7b",
 "has_api_key":false,"is_builtin":false,"is_enabled":true}
```

同一用户重复创建同名配置 → 409 `CONFLICT`；用 `X-User-Id: 1` 给 user 2 建配置 → 403 `FORBIDDEN`。

按用户隔离：`GET /api/models?user_id=2` 只返回 `mock / deepseek-chat / local`，看不到 user 1 的 `my-ollama`。

### 12. 模型配置：连通性测试

```
POST /api/models/4/test
```

Ollama 未启动，响应 502：

```json
{"success": false, "code": "MODEL_CALL_FAILED",
 "message": "模型 my-ollama 连接失败：ConnectError，请确认 http://127.0.0.1:11434/v1 可访问",
 "detail": null, "request_id": "req_b84d750bded2"}
```

### 13. 模型配置：内置模型保护

```
PATCH  /api/models/1  {"display_name":"x"}   → 403 {"code":"FORBIDDEN","message":"内置模型不支持修改，请通过 .env 或新增自建模型"}
DELETE /api/models/1                         → 403 {"code":"FORBIDDEN","message":"内置模型不支持删除"}
```

### 14. 模型配置：停用与删除

`PATCH /api/models/4 {"is_enabled": false}` → 200，`is_enabled=false`；
随后 `GET /api/models?user_id=1` 只剩 `mock / deepseek-chat / local`，`my-ollama` 不可见也不可选。

`DELETE /api/models/4` → 200 `{"deleted":true,"id":4}`；再次删除 → 404 `NOT_FOUND`。

### 15. 密钥安全验证

`GET /api/models?user_id=1` 响应中 key 相关字段只有 `has_api_key`，全文检索无 `sk-` 明文；
数据库中 `model_configs.api_key_encrypted` 存的是 base64 密文，无法直接还原为 Key。

### chat_sessions

| id | user_id | model_name | question | is_deleted | deleted_at |
|----|---------|------------|----------|-----------|------------|
| 1 | 1 | mock | 你好 | 1 | 2026-10-27 16:34:01 |
| 2 | 1 | mock | 再问一次 | 0 | NULL |

### api_call_logs

| id | user_id | session_id | model_name | status | latency_ms | error_message |
|----|---------|-----------|------------|--------|-----------|---------------|
| 1 | 1 | 1 | mock | success | 58 | NULL |
| 2 | 1 | 2 | mock | success | 32 | NULL |
| 3 | 1 | NULL | deepseek-chat | error | 0 | 模型 API Key 未配置，请先在 .env 中设置 MODEL_API_KEY |

2026-10-28 新增模型测试后，`api_call_logs` 追加记录：`deepseek-chat` 一条 `success`、`latency_ms=873`；
`local` 一条 `error`、`error_message` 为连接超时提示；`POST /api/models/{id}/test` 的调用同样写日志。

### model_configs（本次新增）

| id | owner_user_id | name | display_name | provider | base_url | upstream_model | api_key_encrypted | is_enabled |
|----|---------------|------|--------------|----------|----------|----------------|-------------------|------------|
| 1 | NULL | mock | Mock 模型（本地联调） | mock | NULL | NULL | 空 | 1 |
| 2 | NULL | deepseek-chat | DeepSeek Chat | deepseek | https://api.deepseek.com/v1 | deepseek-chat | base64 密文 | 1 |
| 3 | NULL | local | 本地模型 | local | http://127.0.0.1:11434/v1 | qwen2.5:7b | 空 | 1 |

`owner_user_id` 为空的三条是 `seed_builtin()` 在每次启动时同步 `.env` 得到的内置模型；
联调中新建的 `my-ollama`（id=4）已在删除用例中物理删除，再次删除返回 404。

结论：

- 每次问答都写入 `chat_sessions`，`user_id` 能区分用户
- 每次模型调用都写 `api_call_logs`，失败时 `session_id` 为空且 `error_message` 非空
- 软删除只改标记，不物理删除，历史查询自动过滤
